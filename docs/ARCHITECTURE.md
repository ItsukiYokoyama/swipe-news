# しくみ

## 構成

```
src/swipe_news/
  desktop.py     起動: uvicorn をスレッドで動かし、ブラウザを開き、タスクトレイにアイコンを出す。空きポート探し
  server.py      FastAPI。画面 (static/) と API
  crawler.py     巡回: フィードを取って DB に保存 → 内蔵 AI でジャンル判定と好みの計算
  net.py         配信元へのアクセス: robots.txt の確認、同じサイトへの間隔、通信エラーのやり直し
  feeds.py       取得するメディアの設定: おすすめの一覧の読み込み、手入力の URL の確認、0.3 の feeds.yaml の取り込み
  db.py          SQLite (スキーマとその版、カードの並び順、操作の記録、学習の重み、傾向グラフ)
  genre_ai.py    内蔵モデル ruri-v3-30m (ONNX int8) で記事をベクトルにし、小ジャンルを判定する
  taste.py       話題ごとの好みの学習と「反応した言葉」
  taxonomy.py    ジャンルの定義 (genres.yaml) を読む
  settings.py    環境変数で変えられる設定
  paths.py       ファイルの置き場所
  static/        画面 (index.html / app.js / style.css / tailwind.css)
frontend/        tailwind.css を作る設定
catalog/         おすすめのメディアの一覧 (ditsuki.com に置く元のファイル)
extension/       Chrome 拡張機能「十字キーで戻る」
packaging/       Windows 版の zip を作るスクリプト
tests/           自動テスト (pytest)
```

## 権利と配信元への配慮

- RSS のタイトル・概要は改変せずに保存・表示する (HTML のタグを外すだけ)。出典と元記事へのリンクを必ず出す
- 記事ページの本文は取らない。og:image を有効にしたメディアだけ、記事ページの `<meta property="og:image">` を読む
  (ほかの記事と同じ画像はサイト共通のロゴなどとみなして使わない)。画像は保存せず URL だけ持ち、`referrerpolicy="no-referrer"` で表示する
- すべてのリクエストで robots.txt を確認する。読めない・401/403 のときは取りに行かない
- フィードは ETag / Last-Modified で、変わったときだけ受け取る。同じサイト (サブドメイン違いもまとめる) へは 1 本ずつ 2 秒あける
- 配信から 7 日 (`SWIPE_NEWS_RETENTION_DAYS`) を過ぎた記事は消す。操作の記録 (日時・操作・ジャンル・媒体名・ベクトル) は文章を持たないので残す
- メディアは利用者が追加する。API も `agreed: true` (個人で使う・規約を読んだ) が無いと追加しない

## 並び順

未読の記事を、次の値が小さい順に並べる (`db.feed`)。

```
経過時間 (時間) − 小ジャンルの重み × 6 − 好みの近さ × 200 − (好きな言葉を含めば 24)
```

- **小ジャンルの重み** (−3〜+3): 全体と比べて、その小ジャンルで「開く」割合がどれだけ高いか。
  `1.5 × log2(ジャンルの割合 / 全体の割合)`。操作が少ないジャンルは 5 件ぶん全体の割合に寄せる。開いた記事は 2 票。
  足し算にしないのは、大半を「興味なし」にする使い方で、全部のジャンルが下限に張り付いたため
- **好みの近さ** (affinity): 未読の記事ごとに「開いた記事のうち近い 5 件の平均」−「興味なしにした記事のうち近い 5 件の平均」
  (それぞれ、その記事がどの記事にもどれだけ似ているかの平均を引いてから)。同じゲームでもこのシリーズは好き、のような細かい好みを拾う
- 6 枚に 1 枚、好みを無視した 2 日以内の記事を「たまにはこれも」として混ぜる (一度少なめになったジャンルにも挽回の機会を残す)。
  話題の学習で明らかに嫌いなもの・非表示・ミュートは混ぜない。ジャンルで絞り込んでいるときは混ぜない
- 「タイトルで十分」(↑) は好き嫌いではないので学習に使わない。ドパモードの時間切れも ↑ として記録する

## 内蔵 AI (genre_ai.py)

- モデル: ruri-v3-30m (日本語向け、Apache-2.0) を ONNX int8 にしたもの (37MB + tokenizer 6.7MB)。版とファイルのハッシュを固定する
- 記事のタイトル + 概要の先頭 160 文字をベクトル (256 次元、float16 で保存) にする。CPU で 1 件 5ms ほど
- 小ジャンルの判定: 各小ジャンルの説明文 (`genres.yaml` の hints) との近さ。総合系でないメディアは、そのメディアのジャンルに 0.04 足す
  (`SPECIALIST_PRIOR`)。精度 (2026-10-20、手でジャンルを付けた記事で測定): 総合系の記事 74%、専門メディアは 96% がメディアのジャンルのまま
- 判定するのは未読の記事だけ。説明文やモデルが変わったら、次の巡回で未読を判定し直す (`version_of`)
- `SWIPE_NEWS_AI_GENRE=false` で使わないようにできる (メディアのジャンルのまま表示し、好みの近さは学習しない)

## データベース

SQLite (`news.db`)。`PRAGMA user_version` がスキーマの版 (`db.SCHEMA_VERSION`)。
0.3 までの DB (版 0) は、起動したときに AI 要約の列と大ジャンル単位の重みの表を消し、記事と操作の記録はそのまま使う。
0.3 のデータのフォルダにあった `feeds.yaml` は、メディアの表 (`feeds`) に取り込んで `feeds.yaml.imported` に名前を変える。

| 表 | 内容 |
|---|---|
| `articles` | 記事 (未読と、操作した記事)。7 日で消える |
| `actions` | 操作の記録。学習と傾向グラフに使う |
| `genre_weights` | 小ジャンルの重み (操作のたびに計算し直す) |
| `feeds` | 取得するメディア |
| `app_settings` | 画面の設定 (表示しない小ジャンル・ミュートする言葉・好きな言葉) と、傾向グラフの更新番号 |

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/config` | 版・おすすめの一覧の URL・内蔵 AI の状態 |
| GET | `/api/genres` | 大ジャンルと小ジャンル |
| GET | `/api/news/feed?category=&genre=&limit=10` | 未読のカード (並び順のとおり) |
| POST | `/api/news/{id}/action` `{"action": "skip" \| "enough" \| "open"}` | 仕分けの結果。応答に更新後の傾向 (`prefs`) |
| POST | `/api/news/{id}/undo` | 1 枚戻す |
| GET | `/api/news/opened` | 最近開いた記事 |
| GET | `/api/prefs` | 傾向グラフ (`version` は増えるだけの更新番号) |
| POST | `/api/crawl` | いま巡回する (終わるまで待つ) |
| GET / PUT | `/api/settings` | 表示しない小ジャンル・ミュートする言葉・好きな言葉 (送った項目だけ書き換える) |
| GET | `/api/feeds` | 取得するメディア |
| GET | `/api/feeds/catalog?refresh=` | おすすめの一覧 (追加済みのものに `added`) |
| POST | `/api/feeds/inspect` `{"url"}` | URL がフィードか確かめる (ページならフィードを探す。robots.txt も見る) |
| POST | `/api/feeds` | メディアを追加する (`agreed: true` が必要)。追加したらすぐ巡回する |
| PATCH / DELETE | `/api/feeds/{id}` | ジャンル・総合系・記事の画像・取得するかを変える / 外す (未読の記事も消す) |

## 画面 (static/)

- `index.html` (骨組み) / `app.js` (動き) / `style.css` (Tailwind で書けない部分: アニメーション・ドパモードの演出) /
  `tailwind.css` (Tailwind CLI で作ったもの。作り直し方は CONTRIBUTING.md)
- アニメーションは CSS transition + setTimeout で動かす。requestAnimationFrame はヘッドレス Chrome の仮想時間で進まず、確かめられないため
- 傾向グラフの色は、暗い面 (#0d0d0d / #18181b) に対して見分けやすさを確かめて決めた
  (操作: 興味なし #e11d48 / 開く #0284c7 / タイトルで十分 #7c3aed、好み: #3987e5 / #e66767、0 の線 #383835)
- 傾向は 5 秒おきに `/api/prefs` を見て、ほかのタブでの操作も反映する (画面を表示しているときだけ)
